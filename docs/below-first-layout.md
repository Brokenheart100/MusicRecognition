# 下方优先标注：实现与真实谱验证

2026-10-23。原谱 PDF 已采用 `below-first-v1`：**下方 → 上方 → 右侧 → 左侧 → 待人工放置**。没有增加依赖，也没有更换识谱引擎。

当前默认自适应算法先为每组留位，再尝试更易读的字号。同字号依次搜索下方、上方、右侧和左侧。下面是固定 10 pt 的历史基线，最新对比见 [自适应字号验证](adaptive-font-sizing.md)。

## 布局规则

- 按优先级穷举当前区域的可接受位置，再尝试下一方向；在所属谱表下方尽量保持横向对齐，不让更近的上方空白抢先。
- 原谱复用已有二值墨迹掩码与积分图、实际字体包围盒（含变化音、八度点）、页面边界与标注碰撞检查。重排谱使用新的 SVG 图形包围盒，不混用原 PDF 坐标。
- 利用现有谱表几何，在本谱表边缘与相邻谱表之间保留安全边距来限定可用区域；标注可进入谱表间空白，但不跨入相邻谱表本体。横向偏移还需满足同一谱表音符列的邻近约束，替换旧的二维最近符头限制。竖向搜索最多延伸约 7 个谱线间距，左右最多约 2 个；这不是在整页任意找空白。
- 和弦按源符头的高低顺序组成一列，整体选方向和空白；整组放不下时保留待放置，不拆散到不同角落。
- 原谱先预留已保存的手动标注，自动布局避让它们；隐藏项不占位。手动位置仍需满足墨迹、页面和碰撞检查，不会被自动平移。
- 默认黑色 10pt，不为提高放置率自动缩小。重排固定字号按 210 mm 页面宽度与 SVG viewBox 换算；显式“自动字号”继续随符头大小调整，用户手动样式保留。

布局偏好不参与音高识别、八度线恢复或音符身份匹配；原严格校验保持启用。本次没有新增 OpenCV 处理。当前原谱“不可接受”的下方位置也包括跨入其他谱表本体、归属不清、超过搜索范围等情况，而不只是墨迹覆盖。

## 2026-11-21 宽间隙和弦字号修复

真实样本 page-4 暴露了四音和弦被压到 11px（约 3.7pt）的问题，而单音为 25px（约 8.3pt）。根因不是和弦字号系数，而是 `scripts/runtime/annotate.py` 的 `staff_at` 把相邻谱表中线当作上下界，使谱表间可用高度只剩间隙的一半；四音 20px 堆叠需要约 103px，而中线以下只有约 70px，布局只能退到 11px。

修复后上下界使用相邻谱表边缘减去 `max(2, ceil(interline * 0.25))` 的安全边距；仍保留墨迹、列边界、碰撞和页面边界检查，不跨入相邻谱表本体。新增 `test_wide_inter_staff_gap_lets_four_note_chord_keep_preferred_size` 覆盖宽间隙四音和弦。

7 页 snow-halation 复跑，与 `revisions/2/annotations.json` 对比：

- 待人工放置 140 → 5；page-4 8 → 0。
- 小于 5pt 的标注 424 → 49；page-4 109 → 2。
- page-4 四音和弦中位字号 13px → 20px（约 4.3pt → 6.7pt）；目标四音和弦 11px → 20px。
- 标注框相互重叠 0、页面越界 0。
- 有 12 个原本已放置的标注变小，最大 23px → 16px（约 7.7pt → 5.3pt），仍高于 4.5pt 预留档；这是宽间隙改变占位顺序后的取舍，待放置数和过小标注数都显著下降。
