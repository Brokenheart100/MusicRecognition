# P0：一页真实钢琴谱原谱标注可行性报告

日期：2026-10-21。结论：**原扫描图的音符定位、简谱加注与 PDF 导出链路已验证；P0 整体为部分通过。**

当前结果：附加标注为纯黑，按用户反馈增大一档：PDF 从 4 pt 改为 5 pt，扫描谱约从 4.30 pt 改为 5.23 pt；八度点同步放大。真实矢量 PDF 的 9 个旋转 / 裁剪 / 页面起点案例已按新字号重新通过检查，扫描图数据也已更新。

## 输入与范围

使用 Audiveris 官方仓库公开样例，巴赫《二部创意曲》第 5 首，BWV 776。原图页脚注明 Public Domain；固定提交、哈希见 [样谱来源](../samples/README.md)。图像大小 1936 × 2592，双谱表、6 行系统、17 小节，调号为三个降号。

本次输入是原扫描 JPG。`original.pdf` 是将这张原图按 210 mm 页宽等比嵌入 PDF，`annotated.pdf` 在该 PDF 上叠加矢量文字与八度点。原图没有重排，也没有用重新渲染的五线谱替代。**这不代表已经支持任意上传 PDF 的原页面保真叠加。**

PoC 使用固定 C 对照模式：C4=1，E♭4=♭3，E♭3=下加一点的 ♭3，E♭2=下加两点的 ♭3。数字是音高提示，不是指法，也不是根据 E♭ 大调计算的首调简谱。

## 已实现的链路

1. 校验发布包与样谱 SHA-256；将 Audiveris / JDK 便携解压到 `.tools/`。
2. Audiveris 5.11.0 无 GUI 批处理，输出 `.omr` 与 `.mxl`。
3. 使用其文档支持的 `-run` 扩展入口，加载版本固定的 Java 适配器。
4. **从同一个 `HeadInter` 取符头矩形和 step / alter / octave**，不依赖顺序猜配。变化音与调号复用引擎方法。
5. 用引擎二值图与原扫描图的深色像素作为禁入区域，搜索附近空白，已放置的标注矩形互不相交。要求标注不显著更接近另一个已检测符头。
6. 用 ReportLab 产生矢量标注层、pypdf 合并；保存 JSON、离线 HTML 诊断预览、PDF 与栅格结果。
7. 以 Poppler 实际渲染后的 PDF 检查变化区域；由助手依据原扫描图逐音视觉转录首小节的 15 个音作抽查，不是由引擎音高自动生成预期值。这不代替教师或用户的人工复核。

Python 是隔离的验证工具。此次没有新增正式 API、Nuxt 应用、数据库或 Worker，也没有更改现有 AppHost。

## 已知识别与引擎问题

- 引擎报告第 1 小节、16 小节节奏异常，以及第 16 小节 multirest 数量缺失。即使音高抽查通过，也不能说原谱完整正确识别。
- 本机未配置 Tesseract 语言包，日志报告未安装 OCR languages；此次没有验收标题、指法文本和表情文字识别。
- 最初的一键脚本给新图像输入传入 `-force`，在 5.11.0 的 `SheetStub.reachStep` 触发空指针异常。已去掉该参数，并改为每次新建识别运行目录，成功后才更新规范产物，避免失败覆盖有效结果。失败日志保留在 `output/poc/audiveris-force-failure.log`。
- 适配器绑定 Audiveris 5.11.0 内部对象接口，升级需要重新核对并编译验证；不是引擎公开的稳定网络 API。
- 当前拒绝有完整起止和弦关联的有效 `OctaveShiftInter`，防止漏应用 8va / 8vb。未关联候选仅在引擎自身也不应用时记录 warning；音高集合检查继续保留。本扫描样本没有此类候选。

## 真实 PDF 扩展验证（本轮）

### 输入与测试设计

主验证谱为 Mutopia 的单页《小步舞曲》，BWV Anh. 114，下载原件 SHA-256 为 `5f167ba9902c6630514dbe63e4f2a99c04f9de6ff28d88470329b58804436ad7`。它是包含 4 个字体资源、3,858 条绘图指令、0 个图像 XObject 的真实矢量 PDF，原件页脚注明 Public Domain。出处及排版署名见 [样谱说明](../samples/README.md)。

9 个案例来自这一份真实原件及其受控几何变体，不能算 9 份独立识别样本。完整页与裁剪页分别运行一次 Audiveris；其余案例只有在临时正向识别图像素与相应基准完全一致时复用识别结果。

导出保留原页面的 MediaBox、CropBox、`/Rotate`、字体 / 绘图内容，添加黑色矢量标注。没有把原 PDF 页面替换成识别图。裁剪只影响可见窗口，底层原绘图内容仍保留。

### 坐标契约与独立检查

1. 只在临时 PDF 副本清除页面 `/Rotate`，以 Poppler **216 DPI** 渲染 CropBox。
2. 识别图坐标 `(x,y)` 的原点在裁剪区域左上；PDF 用户空间坐标为 `X=L+x/3, Y=T-y/3`。CropBox 的非零起点必须进入平移项。
3. PDF 栅格尺寸是物理尺寸乘以 3 后向上取整。补齐的边缘不足一个像素，**不能用 CropBox 宽高 / 整数像素宽高反推缩放率，也不能用补齐的图像高度当作物理页面高度**。
4. 标注写在原 PDF 未旋转的用户空间，原 `/Rotate` 由查看器同时作用于乐谱和标注；导出没有把源页面改成 0 度。
5. 从实际生成的 PDF `Tm` 指令读取文字基线，与独立计算的 PDF 目标坐标比较，误差阈值 0.001 pt。
6. 独立渲染对照：把已验证的 0 度标注 PDF 通过 PDF 页面旋转 / 平移操作生成预期文件，再用 Poppler 渲染。不使用生产坐标函数绘制预期图。
7. 逐案例检查原绘图指令序列保留、页面几何保留、标注区域外像素不变、不遮挡原深色墨迹、标注矩形不相交、实际标注可见。

### 黑色要求

PDF 数字、升降号、八度点使用 RGB `(0,0,0)`；SVG 使用 `#000`；JSON 记录 `#000000`。浏览器实测附加文字颜色为 `rgb(0,0,0)`，字体正常加载。原 JPG 也已重新生成黑色结果与浏览器截图。

颜色验证检查实际新增像素是否符合黑色与原背景的抗锯齿混合，并要求出现实际纯黑字芯。彩色旧纸扫描图上的字形边缘会保留纸张底色，不能要求所有变化像素都为中性灰。本扫描谱及全部 PDF 案例的黑色混合不一致像素数均为 0。

### 保留的失败样本与限制

先尝试的 Audiveris 官方《圣母颂》真实 PDF，检测到 437 个符头，MusicXML 只输出 275 个有音高音符，缺失 162 个。引擎日志包含 `PartwiseBuilder.WedgeIterators` 在 timeOffset 为空时的异常。严格一致性检查阻止了标注导出；没有删除检查来让样本通过。证据在 `output/poc-pdf/base/` 和 `ave-maria-failure.json`。

《小步舞曲》完整页在页脚文字区域产生一个未关联到起止和弦的八度移位候选 Inter 4399。经核对固定版本源码，MusicXML 导出也不对这种候选应用八度移位；适配器将其记录为 warning。裁剪掉页脚后的识别没有此候选。具有完整关联的有效 8va / 8vb 仍不受支持。

此次只验证**单页、默认 UserUnit=1、CropBox 在 MediaBox 内、正交页面元数据旋转**。不代表内容流内部任意旋转、自动纠正拍照方向、多页、非默认 UserUnit、裁穿音符后的重新识别、完整语义正确率或打印可用性已通过。临时正向化也没有推断乐谱真实朝向。
