# 图片片段识谱与 MusicXML 拼谱方案

日期：2026-10-24。状态：**首版辅助拼谱已实现，Orange 两张真实截图的网页上传、拼接、MusicXML 与重排 PDF 闭环通过本地验证**。入口为 `/fragments`，也可从原谱工作台侧栏进入。11 小节、193 个已识别音符生成 2 页 PDF；第 5、6 小节节奏仍有疑点，原图八度线未完整识别，不能视为原谱的准确复刻。详见 [实现与验证报告](fragment-score-composition-validation.md)。

下文保留完整设计目标；跨片段连线修复、自动重复段建议、浏览器内音符/时值编辑和新排版上的简谱标注仍属后续工作。

## 目标与使用流程

让用户将同一版本钢琴谱的若干截图，整理成可编辑 MusicXML 和可打印的新排版 PDF：

1. 批量添加图片，拖动调整顺序，保留每张原图。
2. 框选有效谱面，建议去掉视频黑边、标题空白及叠加字幕；裁剪预览保留谱号、调号、拍号、八度线、上下谱表与完整小节。
3. 逐片段识别，显示识别结果、缺失上下文及小节/声部问题。
4. 用户确认每个片段保留的首末小节、连续关系、重叠去重与必要的谱号/拍号上下文。
5. 按乐器、谱表、声部和小节语义合并；检查时值、边界连线和八度状态。
6. 预览整曲、校对，下载 `.musicxml` / `.mxl` 和重新排版 PDF。后续可在新谱上加入现有自适应简谱标注。

该流程不是把截图接成长图，也不是把多个 XML 文本直接串接。用户若只有不连续片段，应导出明确分段的练习谱；缺失小节不自动补成休止符或伪造音符。

- `【扒谱_阮克理】オレンジ _ Orange (2021) - 四月是你的谎言 ED2_00-00-16-572.png`

均为 1920×1080。以现有 OpenCV 做只读检测，白色谱页列范围约 `[194,1726)`，第一张谱线间距中位数约 12.75 px，第二张约 13 px。这仅表明谱线几何可检测，不是识谱准确率或识谱成功证明；个别被符号遮挡的横线没有完整检出。

肉眼检查：第一张包含标题、拍号、八度线和一组钢琴谱表，低音谱表末尾有谱号变化；第二张包含两组谱表，能看到第 5、8 小节编号。小节编号可作为排序建议，最终仍需按小节内容确认，不应仅凭文件时间戳或编号自动拼接。第二张不重复完整起始拍号等信息，需要继承/确认上文，不能将独立识别器的默认值直接当成正确答案。

## 复用与新增组件

| 环节 | 组件 | 约束 |
| --- | --- | --- |
| 截图框选与输入清理 | Cropper.js 1.6.2；现有 Pillow / NumPy | 首版仅矩形裁剪，记录原图到识别图的变换；自动模式仅去明显黑边，不主动切除标题或谱面上下文 |
| 图片转 MusicXML | 现有 Audiveris + Python 工具适配器 | 复用日志、取消、超时、依赖检查；缺少拍号等上下文时明确提示，必要时确认上下文后重识别 |
| 音乐结构读取与拼接辅助 | music21 10.5.1 + MusicXML 结构化选取 | music21 审核解析数量和时序；权威 XML 保留引擎识别的音符元素，不经二次解析写回；库不会自动判断重复截图或补齐漏音 |
| 网页预览 | 现有 OSMD / Verovio | 保留完整性检查；已有复杂 MusicXML 导入丢失问题不能因新增模式而跳过 |
| 重排 PDF | MuseScore Studio CLI 4.7.5 | 由 MusicXML 重新刻谱，往返检查音高、谱表、起始时刻和时值；reportlab/pypdf 负责输入 PDF 与页数检查，不手工实现音乐刻谱 |
| 简谱标注 | 现有编号领域规则和自适应布局 | 拼谱后的新坐标需要重新映射，不能复用截图上的标注位置 |

music21 在这个需求中的收益高于单纯原谱叠加：需要处理完整音乐结构，而不只是给符头加数字。但它不负责从截图识别音符，PDF 刻谱也需要独立渲染器。版本已固定在 `scripts/setup/requirements-composition.txt`；当前往返门禁覆盖音高、谱表和时序，连线、八度线等记号仍需人工比对原图，不能据音符数量一致推断所有记号完整。

## 拼接规则

- **按乐器/谱表映射**：首版只支持同一钢琴编配的上下谱表。不能将独立识别出的 Part ID 或 Voice 编号直接视为跨片段稳定 ID。
- **传递上下文**：每个拼接点显式记录调号、拍号、谱号、八度状态和必要速度信息。识别阶段上下文不足可能已经造成节奏错误，不能仅在最终 XML 顶部补一个拍号来掩盖。
- **按整小节保留区间**：用户选择片段的起止小节；截断小节先拒绝或待校对，不直接拼入。首版只处理完整小节，后续再支持拆开的同一小节。
- **重叠与重复**：用音高、起始时刻、时值、谱表和声部等特征提出相邻重复小节候选，用户确认删除范围。相似伴奏型可能是正常重复，不能自动删音。
- **核对时值与同步**：比较声部长度、上下谱表对齐及拍号预期，独立处理弱起、自由小节、连音和装饰音；存在异常时保留诊断并要求校对。
- **处理跨边界记号**：延音线、连奏线、八度线、踏板、反复和结尾编号须有配对/归属规则。尚不能可靠配对的项目显示为待确认，不能随意连接。
- **重新编号和来源追踪**：生成新的全局小节及音符 ID，同时记录源片段、源符头/小节、保留区间和变换。每个合并后的音符都可回到原截图核对。
- **校对能力扩展**：现有音高/位置校对不足以修复所有拼谱问题，还需要至少能处理漏音、多音、时值、声部和连接点；首版可先提供外部记谱软件继续编辑的 MusicXML 下载。

## 架构边界

保留 Nuxt 4 + ASP.NET Core Clean Architecture + Aspire；不增加 FastAPI 服务。

- Domain：`FragmentPlan`、片段顺序、裁剪及保留小节范围的约束。
- Application：`FragmentService`、上传/修订/导出用例、`IFragmentStorage` 与 `IFragmentEngine` 端口。
- Infrastructure：复用 `ScoreJob` / `ScoreRevision`、持久化 outbox、Hangfire、文件存储和受保护进程日志；Python 适配 Audiveris、music21 与 MuseScore，不新增服务或数据库表。
- Frontend：片段列表/排序、原图框选、整体任务阶段、小节范围校对和整曲预览；TanStack Query 管理任务状态，Pinia 管理未保存编辑，SDK / Zod 从 OpenAPI 生成。

识别将已排序截图作为一本多页谱输入 Audiveris，复用谱号/拍号上下文，再用 MusicXML 分页边界对应片段并选取完整小节。分页、声部或谱表布局无法可靠对应时拒绝拼接，不靠音符数量猜测片段边界。

每张原图不可变，裁剪、顺序、边界确认与导出属于新修订。首版裁剪只在新模式启用；现有原谱坐标流程的单位矩阵约束不能被直接放宽。

## 分阶段实施与验收

1. **两张真实样本验证**：独立输出目录中验证裁剪、逐图识别，记录音符数、小节数、声部、时值、八度/谱号上下文及错误；无完成证据前不声称拼谱已跑通。
2. **人工顺序 + 完整小节拼接**：固定钢琴上下谱表，人工确认上下文与重叠范围，输出 MusicXML；逐音对比拼接前后的音高、起始时刻、时值、声部和谱表，不静默合并冲突。
3. **网页闭环 + PDF**：批量上传、排序、裁剪、失败重试、连接点提示、预览、MusicXML 下载和整曲 PDF；验证分页、打印可读性、渲染音符覆盖、原图来源映射及修订恢复。
4. **辅助自动化**：有代表性样本和人工真值后，再增加自动重复段建议、缺口定位、跨片段连线审核与自适应简谱标注。

首版目标是“可校对的辅助拼谱”，不承诺任意片段无需确认就能恢复完整曲谱。P4 已有复杂谱导入限制仍是本功能要解决的验收项，不能沿用简单样本结果扩大到所有钢琴曲。

- [MuseScore Studio CLI](https://handbook.musescore.org/appendix/command-line-usage)：converter mode / `-o` 导出；该官方页面注明部分内容沿用旧版，实际接入仍需核对固定安装版本并试跑。
